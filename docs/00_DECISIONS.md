# 00 — Технические решения

Каждое решение — с обоснованием, чтобы на защите не пришлось придумывать
причину на ходу.

## Хранение данных

| Решение | Почему |
|---|---|
| Статические GeoJSON, не PostGIS | ~450 КБ трансект + объекты на весь MVP. Пространственных запросов в рантайме нет — всё считает пайплайн заранее, backend только читает файлы в память при старте |
| SQLite для гражданских заявок | Единственные данные, которые реально пишутся во время работы приложения |
| EPSG:32639 (UTM 39N) для расчётов, EPSG:4326 для отдачи наружу | Мангистау целиком укладывается в одну зону UTM; метры в градусах считать нельзя — ошибка порядка 30% |

## Извлечение береговой линии

| Решение | Почему |
|---|---|
| MNDWI + порог Оцу | SWIR лучше подавляет солончаки и влажный песок, чем NIR (NDWI); Оцу подбирает порог индивидуально под каждый снимок, а не фиксирует один на все годы |
| Порог Оцу считается на сервере GEE по гистограмме | Клиентские реализации (cv2/skimage) недоступны на стороне Earth Engine — гистограмма и максимизация межклассовой дисперсии сделаны вручную в `pipeline/gee/otsu.py` |
| Только июльские снимки, окно расширяется до июнь–август при нехватке сцен | Сгонно-нагонные явления на Каспии двигают урез воды на сотни метров за сутки — сравнивать снимки из разных месяцев года нельзя |
| Landsat 5 (2000–2011) → Landsat 8 (2013–2015) → Sentinel-2 (2016–2026) | Реальная доступность коллекций: Landsat 5 закрыт, Landsat 8 запущен в 2013, Sentinel-2 даёт устойчивое покрытие AOI с 2016 |
| 2012 год помечен как отсутствующий, а не интерполирован | Landsat 5 завершил работу, Landsat 8 ещё не летал — данных физически нет, и это должно быть видно на графике, а не скрыто интерполяцией |

## Трансекты и позиция берега — решение, изменённое во время разработки

Первая версия векторизовала всю береговую линию как один полигон
(`reduceToVectors` по всему AOI) и брала его контур как LineString года.
На реальных данных это дало два эффекта:

1. Полигон, обрезанный по границе AOI, захватывал кусок самой этой границы
   как часть контура — линия оказывалась в разы длиннее настоящей (846 км
   вместо ожидаемых ~220).
2. После попытки отсечь границу AOI и взять «самый длинный связный кусок» —
   этот кусок оказался в бухте севернее Актау, а сам Актау (главный объект
   демо) выпал из результата: реальная береговая линия Мангистау изрезана
   заливами сильнее, чем предполагала грубая осевая линия побережья.

**Решение:** отказаться от полигональной векторизации всей линии.
Вместо этого — прямой сэмплинг MNDWI вдоль каждой трансекты
(`pipeline/gee/sample_transects.py`): находим точку перехода
суша→вода по порогу Оцу прямо на луче трансекты, с линейной
интерполяцией между соседними сэмплами. Это именно то, что нужно для
DSAS (позиция берега на конкретной трансекте), без хрупкой промежуточной
геометрии. Линия берега для карты при этом просто строится соединением
точек пересечения всех трансект за год — не отдельным шагом.

| Решение | Почему |
|---|---|
| Baseline строится из грубой осевой линии побережья (`COAST_WAYPOINTS`), а не из векторизованной линии года | Разрывает зависимость направления/расположения трансект от качества MNDWI-векторизации конкретного года. Точность измерения не страдает — её даёт прямой сэмплинг, а не геометрия baseline |
| Направление трансект (в море, не в сушу) проверяется эмпирически на реальных пикселях одного опорного года | Обе стороны нормали пробуются, побеждает та, что даёт переход суша→вода на большинстве трансект; если обе дают < 55% — пайплайн падает с понятным сообщением вместо тихого мусора в данных |
| Оцу и сэмплинг — в прибрежном коридоре (буфер вокруг `COAST_WAYPOINTS`), не по всему AOI | AOI занимает ~70 000 км² открытого моря и степи; коридор — на два порядка меньше и достаточен для разделения воды/суши |
| Рабочий масштаб для Оцу/сэмплинга — не мельче 30 м даже для Sentinel-2 (10 м) | Итоговая точность всё равно ограничена шагом трансект (500 м) и допуском упрощения линии (10 м) — считать гистограмму на нативных 10 м без выигрыша в точности не нужно |
| Регрессия — линейная (scipy.stats.linregress), не нейросети | 26 годовых наблюдений — выборка для регрессии, а не для обучения сети; результат при этом объясним на защите |
| Позиция трансекты = `LineString.project(point)` (расстояние по длине дуги), не индекс ближайшей вершины | Сопоставление по ближайшей вершине даёт ложные провалы валидации на изогнутых линиях |

## Найдено и исправлено на полном 26-летнем прогоне

Два реальных дефекта, обнаруженные только на полных данных (не видны на
выборке в 4 года):

1. **Перепутан знак скорости.** Трансекта измеряется от суши (`p0`, якорь
   у объекта) в сторону моря. Расстояние от суши до воды растёт, когда море
   отступает — но конвенция всего проекта («отрицательная скорость =
   отступление») предполагает противоположное. Позиции теперь сохраняются
   с минусом (`pipeline/gee/run_real_pipeline.py`), а `distance_to_shore_m`
   у объектов берётся по модулю. До исправления доля «отступающих»
   сегментов была 9%, после — 91%, что и должно быть для Каспия.
2. **Единичные ложные срабатывания портили регрессию.** Например, трансекта
   со стабильной позицией ~5250–5280 м все 18 лет вдруг дала 176 м в
   одном году — и вся скорость улетала до −53 м/год. Добавлена защита от
   выбросов (критерий Хампеля от residuals первого прохода регрессии,
   `pipeline/common/stats.py`) — на полном прогоне отфильтровано 678
   единичных выбросов из 539 трансект.

## Известные ограничения текущей реализации

- `COAST_WAYPOINTS` — ручная прикидка по географии, не линия из OSM. Для
  продакшн-точности стоит заменить на реальный OSM coastline перед
  финальным прогоном на всех 26 годах.
- Координаты 8 объектов инфраструктуры — предварительные (см. `README.md`,
  раздел «Данные, размечаемые вручную»); нужно разметить в geojson.io.
- Уровень Каспия (`pipeline/data/manual/caspian_level.csv`) — синтетический
  плейсхолдер для модуля критического уровня; нужен реальный ряд
  (Hydroweb / DAHITI / G-REALM).

## Frontend

| Решение | Почему |
|---|---|
| JavaScript, не TypeScript | Типизация GeoJSON забирает часы, которых на хакатоне нет |
| Vite + React, без `react-leaflet` — прямой Leaflet через `useRef`/`useEffect` | Полный контроль над жизненным циклом слоёв: старый слой явно снимается перед добавлением нового, иначе Leaflet копит слои в DOM при каждой смене года |
| Leaflet с `preferCanvas: true` | ~450 сегментов трансект как SVG заметно тормозят рендер |
| `stop()` автоплея вызывается в `onChange` ДО установки года | Иначе таймер автоплея перезаписывает год, выбранный вручную, на следующем тике |
| PDF — снимок DOM через html2canvas, без текстового рендера в jsPDF | Встроенные шрифты jsPDF не поддерживают кириллицу без явно подключённого TTF; снимок обходит проблему полностью |
| `jspdf`/`html2canvas` — динамический импорт | Модуль экспорта весит ~180 КБ gzip — незачем грузить его до первого клика на «Экспорт в PDF» |
