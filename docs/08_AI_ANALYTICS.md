# 08 — Формулы риска, регрессии, прогноза

## Скорость отступления и доверительный интервал

Для каждой трансекты — линейная регрессия `position_m ~ year` по всем
доступным годам (`scipy.stats.linregress`, `pipeline/common/stats.py`):

```
slope   = м/год (отрицательный = отступление)
r²      = качество тренда
CI 95%  = slope ± t(0.975, dof) × std_error
```

`confidence`: `high` при r² ≥ 0.8 и ≥ 20 валидных лет; `medium` при
r² ≥ 0.5 и ≥ 15 лет; иначе `low`. Сегменты с `low` не выбрасываются из
файла, но исключаются из агрегатов статистики.

## Оценка риска объекта

`pipeline/risk/engine.py`. Нормировка каждого компонента в 0–100,
взвешенная сумма:

```
score = 0.30 × norm(|скорость|, 0..50)
      + 0.25 × norm(расстояние_до_воды, 0..1000)
      + 0.25 × norm(критичность_категории, 0..10)
      + 0.20 × norm(30 − min(лет_до_порога, 30), 0..30)

level = high (≥67) | medium (34–66) | low (<34)
```

«Лет до порога» — сколько лет при текущей скорости остаётся до того, как
расстояние объекта до воды достигнет критического для его категории
(`CRITICAL_DISTANCE_M` в `pipeline/gee/config.py`, напр. 300 м для
водоснабжения). Критичность категории (1–10) — из `CATEGORY_CRITICALITY`,
фиксированный справочник, не расчётная величина.

## Прогноз (три сценария)

`pipeline/forecast/scenarios.py`. Экстраполяция текущей скорости на
горизонты 2030/2035/2040:

| Сценарий | Множитель | Допущение |
|---|---|---|
| optimistic | ×0.75 | темп замедляется |
| baseline | ×1.0 | линейная экстраполяция текущего тренда |
| pessimistic | ×1.25, плюс ускорение 1.5%/год | темп ускоряется |

Это сценарная экстраполяция наблюдаемого тренда, не гидродинамическая
модель — не учитывает сток Волги/Урала, климатические сценарии и
инженерные мероприятия. Это явно указано в ответе `/objects/{id}/forecast`.

## Модуль критического уровня моря (после часа 36)

`pipeline/postprocess/critical_level.py`. Для трансекты — линейная связь
`position_m ~ level_m` (не `year`) по ряду уровня Каспия. Наклон —
косвенная оценка уклона дна на участке, полученная без единого промера.
Обратная задача: при каком уровне позиция достигнет критической для
объекта. Трансекты со слабой связью (r² < 0.3) или < 12 наблюдений
исключаются — таким объектам критический уровень не считается, честно
помечается `available: false`.

## Валидация

Синтетическая проверка регрессии (известная скорость → восстановленная
пайплайном скорость) и контроль по трём участкам через `pipeline/validation/`.
`statistics.json.validation.rmse_m` заполняется при прогоне на реальных
снимках; до этого явно `null`, а не выдуманное число.
